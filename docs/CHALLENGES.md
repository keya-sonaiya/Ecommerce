# Challenges Faced and Their Resolutions

### 1. Understanding GA4 Events and Parameters

**Challenge:** Since GA4 was new to me, I initially found it difficult to understand what information should be tracked and how events, parameters, and user properties differ from one another.

**Resolution:** I created a tracking plan based on important user actions, such as viewing products, adding items to the cart, applying coupons, and completing a purchase. This helped me identify what information needed to be collected at each stage.

### 2. Connecting the Website to Google Tag Manager

**Challenge:** I needed to understand how events generated by my React application could reach GA4 through Google Tag Manager. The relationship between the data layer, triggers, and event tags was new to me.

**Resolution:** I connected the application's data layer events with the corresponding custom-event triggers and GA4 event tags in GTM. This helped me understand how website interactions are passed to analytics.

### 3. Avoiding Duplicate Events

**Challenge:** I realised that the same interaction could be tracked more than once if multiple tracking mechanisms were active. This was particularly important for page views because the application also uses React Router for navigation.

**Resolution:** I reviewed the page-view configuration and disabled overlapping browser-history page-view tracking. I then used GTM Preview to check the tag-firing behaviour.

### 4. Making Event Data Useful in GA4 Reports

**Challenge:** I wanted to understand how information such as visitor type and preferred category could be used in GA4 reports. I initially found it confusing that sending a parameter does not automatically make it available as a reporting dimension.

**Resolution:** I identified the relevant user properties and event parameters and learned how to register the appropriate custom dimensions in GA4, using the correct scope.

### 5. Events Missing From a Second Browser Profile
 
**Challenge:** Realtime showed only my GTM Preview session. A second profile on the live site sent nothing, even though the container was published.
 
**Resolution:** The second profile used the Brave browser, whose Shields block Google Tag Manager and Google Analytics requests. The Network tab showed no `gtm.js` or `g/collect` requests. I tested in a browser without tracker blocking. This also showed me that client-side tracking under-counts visitors who use privacy tools.
